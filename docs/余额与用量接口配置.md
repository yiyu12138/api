# 余额与用量接口配置

本文档用于把中转站的余额、额度或用量接口映射到 API Balance。

具体接口请参考中转站的官方文档。不知道如何填写时，把中转站接口文档和本文档一起发给 AI，让 AI 按本文档输出配置。不要发送真实密钥，请统一使用 `sk-xxxxx` 代替。

## 先确认平台提供什么

从中转站文档中找到以下内容：

1. 余额或额度接口的 URL、请求方法和请求示例。
2. 密钥放在 `Authorization`、`X-API-Key`、URL 参数还是请求 JSON 中。
3. 成功响应的完整 JSON 示例。
4. 哪个字段代表剩余、已用、总额度和套餐名称。
5. 额度是美元、人民币还是内部积分，以及积分换算比例。
6. 是否额外要求用户 ID。
7. 是否提供请求日志或分时账单接口，以及分页规则。
8. 用量中的消费字段使用什么币种，是否仍是内部额度。

余额接口和日志接口是两类不同接口。不要把日志接口填到余额查询的“请求 URL”中。

## 表单字段映射

| 面板字段 | 填写规则 | 示例 |
| --- | --- | --- |
| 地址 | 站点根地址。请求 URL 为完整地址时，此项仍填写站点首页或 API 根地址 | `https://api.example.com` |
| 密钥 | API Key 或系统访问令牌 | `sk-xxxxx` |
| 请求方法 | 必须与接口文档一致，只支持 GET 或 POST | `GET` |
| 认证方式 | Bearer、X-API-Key、URL 参数或无需认证 | `Bearer Token` |
| 参数名称 | 仅 URL 参数认证使用 | `key` |
| 请求 JSON | 仅 POST 使用，必须为合法 JSON | `{"token":"{{apiKey}}"}` |
| 请求 URL | `/` 开头时拼接到站点地址；完整 URL 直接请求 | `/api/v1/key/quota` |
| 剩余额度 | 必填，成功响应中的可用余额字段路径 | `data.key.remaining_usd` |
| 已用额度 | 可选，累计已用额度字段路径 | `data.key.used_usd` |
| 总额度 | 可选，额度上限字段路径 | `data.key.total_usd` |
| 套餐名称 | 可选，仅用于展示 | `data.plan.name` |
| 换算除数 | 显示金额 = 原始数值 ÷ 换算除数 | `1` 或 `500000` |
| 额度币种 | 接口原始额度对应的币种 | USD 或 CNY |
| 用户 ID | 仅接口明确要求时填写 | 后台显示的数字用户 ID |

认证方式会生成以下请求：

- Bearer Token：`Authorization: Bearer sk-xxxxx`
- X-API-Key：`x-api-key: sk-xxxxx`
- URL 参数：`?参数名称=sk-xxxxx`
- 无需认证：不发送密钥

POST 请求 JSON 支持 `{{apiKey}}`、`{{accessToken}}`、`{{baseUrl}}` 和 `{{userId}}` 占位符。

## JSON 字段路径

字段路径从响应根对象开始，使用英文句点逐层定位。数组下标也写成数字片段。不支持 `$.data.balance`、`data[0].balance` 或 JavaScript 表达式。

示例响应：

```json
{
  "data": {
    "key": {
      "remaining_usd": 50,
      "used_usd": 3.2
    },
    "plan": {
      "name": "Pro"
    }
  }
}
```

对应填写：

```text
剩余额度: data.key.remaining_usd
已用额度: data.key.used_usd
总额度: 留空
套餐名称: data.plan.name
换算除数: 1
额度币种: USD
```

当总额度留空且接口提供已用额度时，程序使用“剩余 + 已用”计算总额度。字段值可以是数字，也可以是仅包含数字、逗号和货币符号的字符串。

## 换算除数

计算公式：

```text
面板显示金额 = 接口原始数值 ÷ 换算除数
```

- 接口直接返回 `$50` 或 `50.00`：填写 `1`。
- 接口返回内部额度，例如 `25000000` 代表 `$50`：填写 `500000`。
- 不确定时，以平台文档的换算规则为准，并用测试查询结果与平台后台余额核对。

## 用户 ID

普通 API Key 查询通常留空。New API 或部分其他站点可能要求“系统访问令牌 + 用户 ID”。使用中转站自动识别模板时，程序会把用户 ID 作为 `New-Api-User` 请求头发送。

如果接口文档要求的不是 `New-Api-User`，不要猜测可以直接使用；应选择平台已有模板，或评估是否需要增加后端适配。

## 用量统计支持范围

自定义计费接口能提供剩余、已用、总额度和套餐汇总，但不能仅凭累计值还原每天、每个模型和每次请求。

当前自动识别的逐条日志接口：

- derouter：`/usage-logs` 或 `/sub-key/usage-logs`

其他平台可在站点管理中展开“自定义用量统计接口”，填写用量接口 URL、请求方法、认证方式和字段映射 JSON，不需要改代码。当前自定义配置适用于按今天、昨天、近 7 天、近 30 天返回的周期汇总接口。

站点“运行方式”同时控制余额和用量：自动查询会在打开页面及定时刷新时运行；仅手动查询只响应测试、立即刷新和“更新用量”；暂停全部查询不发送请求，也不参与汇总。

### 自定义用量接口字段映射

字段映射是一个 JSON 对象：

- `summary`：根级剩余、已用、总额和单位字段。
- `timezone`：接口时区字段。
- `costCurrency`：消费字段币种，只能填 `USD` 或 `CNY`，默认 `USD`。
- `costDivisor`：消费字段换算为金额前的除数，接口直接返回金额时填 `1`。
- `periods`：各统计周期对象的完整路径；平台没提供的周期可以删除。
- `metrics`：每个周期对象内部的请求数、消费和 Token 字段。
- `model`：`topModels` 数组内每个模型项目的字段。

```json
{
  "summary": {
    "remaining": "remaining",
    "used": "used",
    "total": "total",
    "unit": "unit"
  },
  "timezone": "timezone",
  "costCurrency": "USD",
  "costDivisor": 1,
  "periods": {
    "today": "periods.today",
    "yesterday": "periods.yesterday",
    "last7d": "periods.last7d",
    "last30d": "periods.last30d"
  },
  "metrics": {
    "requests": "requests",
    "successCount": "successCount",
    "failedCount": "failedCount",
    "successRate": "successRate",
    "inputTokens": "promptTokens",
    "outputTokens": "completionTokens",
    "totalTokens": "totalTokens",
    "cost": "cost",
    "models": "topModels"
  },
  "model": {
    "id": "modelId",
    "name": "modelName",
    "requests": "requests",
    "tokens": "totalTokens",
    "cost": "cost",
    "successRate": "successRate"
  }
}
```

Sole 类接口的配置示例：

```text
用量接口 URL: https://soleapi.com/v1/usage
请求方法: GET
认证方式: Bearer Token
字段映射 JSON: 使用上面的示例，但 costCurrency 改为 CNY，costDivisor 保持 1
```

SoleAPI 可留空用量接口和映射，使用内置识别。其 Credits 按人民币计价，例如 `cost: 0.238003` 表示约 ¥0.238，而非美元。手动配置时请使用 `costCurrency: CNY`，避免重复乘美元汇率。

Sole 运营商提供的 `/v1/usage` 返回 `periods` 周期汇总，不返回逐条请求日志。因此面板可以显示消费、请求数、Token 和模型排行，但“最近请求”会提示接口未提供逐条日志。这不是查询失败。

未映射或接口未返回的消费、请求数和 Token 会显示为未知；全站汇总会标注“已知部分”，不会把未知数据当成 `0`。

若平台提供的是逐条请求日志，中转站文档至少需要提供：

| 统计项 | 常见字段 |
| --- | --- |
| 请求时间 | `created_at` 或 `createdAt` |
| 模型 | `model` |
| 消费 | `cost_usdc`、`cost_usd`、`cost` 或 `amount` |
| 输入 Token | `input_tokens` 或 `inputTokens` |
| 输出 Token | `output_tokens` 或 `outputTokens` |
| 缓存读取 | `cache_read_tokens` 或 `cacheReadTokens` |
| 缓存写入 | `cache_write_tokens` 或 `cacheWriteTokens` |

还需要说明日志列表所在的 JSON 路径、时间格式、分页参数、下一页判断方法和最大页数。当前自定义表单只解析周期汇总；分页日志仍需增加后端适配，不能从汇总数据伪造单次请求。

## 交给 AI 的任务模板

```text
请根据中转站接口文档，为 API Balance 生成余额和用量查询配置。
只使用文档明确给出的接口和字段，不要猜测，不要使用真实密钥。

请依次输出：
1. 地址
2. 请求方法
3. 认证方式
4. 参数名称（不需要则留空）
5. 请求 JSON（不需要则留空）
6. 请求 URL
7. 剩余额度 JSON 路径
8. 已用额度 JSON 路径（没有则留空）
9. 总额度 JSON 路径（没有则留空）
10. 套餐名称 JSON 路径（没有则留空）
11. 换算除数及计算依据
12. 额度币种
13. 是否需要用户 ID

最后用接口响应示例逐项验证字段路径，并说明测试成功后应该显示的余额。
然后为“自定义用量统计接口”输出：
14. 用量接口 URL
15. 请求方法
16. 认证方式
17. 请求 JSON（不需要则留空）
18. 字段映射 JSON
19. costCurrency（USD 或 CNY）及依据
20. costDivisor 及换算公式

最后判断接口返回的是周期汇总还是逐条日志。周期汇总应直接生成字段映射；逐条日志则列出日志数组路径、时间字段、分页参数和下一页规则，并明确说明当前需要后端适配。
```

## 保存前检查

1. 使用占位密钥分析文档，只在自己的 API Balance 页面填写真实密钥。
2. 点击“测试查询”。
3. 确认余额、币种、已用和总额与平台后台一致。
4. 数值明显过大时，检查 JSON 路径和换算除数。
5. 返回 401 或 403 时，检查令牌类型、认证方式、权限和用户 ID。
6. 测试结果正确后再保存配置。
