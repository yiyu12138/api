# 通知推送配置

推送设置用于在站点美元余额低于阈值时发送提醒。所有启用渠道共享一个北京时间，每个低余额站点每天最多记录一次成功提醒。多个渠道同时启用时会并行发送；至少一个渠道成功后，该站点当天不再重复提醒。

## 使用步骤

1. 在侧边栏打开“推送设置”。
2. 填写某个渠道的凭据并打开渠道开关。
3. 点击“保存推送设置”。
4. 点击该渠道的“保存并测试”，确认能够收到测试消息。

推送凭据会使用当前平台的设备密钥加密保存：Docker 使用 `APP_SECRET`，飞牛使用应用数据目录中的随机密钥，Android 使用 Keystore。页面重新打开后只显示掩码；输入框留空表示保留原凭据。

后台每分钟检查一次是否已经到达当天设定时间。若恰好在设定分钟离线，服务恢复后仍会补做当天检查；同一站点当天只记录一次成功提醒。自动刷新设为 `0` 时通知检查仍会运行，但使用最近一次保存的余额，建议需要告警时保留合理的自动刷新间隔。

## 支持渠道

### Bark

填写 Bark App 展示的完整地址，例如：

```text
https://api.day.app/你的Key
```

程序使用 GET 请求，并在路径中追加经过 URL 编码的标题和正文，同时发送 `group=API余额` 与 `level=timeSensitive`。

### Server酱

填写 Server酱后台提供的 `SendKey`，只填 Key，不要填写完整 URL。程序发送：

```http
POST https://sctapi.ftqq.com/{SendKey}.send
Content-Type: application/x-www-form-urlencoded

title=标题&desp=正文
```

### PushPlus

填写 PushPlus“发送消息”页面提供的用户 Token。程序发送：

```http
POST https://www.pushplus.plus/send
Content-Type: application/json

{"token":"你的Token","title":"标题","content":"正文","template":"txt"}
```

### Telegram

填写两项：

- Bot Token：通过 BotFather 创建机器人后获得，例如 `123456:ABC...`。
- Chat ID：接收消息的个人、群组或频道 ID。群组和频道常见为负数。

机器人必须已经加入目标会话并拥有发消息权限。程序调用 Telegram Bot API 的 `sendMessage`。

### 通用 Webhook

填写能够接收 POST 请求的完整 HTTP/HTTPS URL。程序发送以下 JSON：

```json
{
  "title": "站点名称 余额偏低",
  "body": "当前余额与阈值",
  "source": "API Balance",
  "at": "ISO 8601 时间"
}
```

Webhook 返回任意 `2xx` 状态即视为成功。需要签名、自定义请求头或其他 JSON 结构的服务，应在 Webhook 前增加自己的转换服务。

## 测试与排错

- 提示“尚未配置”：保存的必填凭据不完整，重新填写后再测试。
- 返回 401 或 403：Token、SendKey、Bot Token 或 Chat ID 错误，或账号没有发送权限。
- 请求超时：检查 Docker 主机的公网、DNS、防火墙；Telegram 等服务在部分网络中可能不可直连。
- 测试成功但没有低余额通知：确认渠道开关已启用、每日时间正确、站点处于启用状态且余额低于阈值。
- 多个渠道只有部分收到：系统会把至少一个成功视为当天已提醒；使用每个渠道的测试按钮逐个检查。
