# API Balance 项目与数据说明

这份文档用于让维护者或 AI 快速理解 API Balance 是什么、数据从哪里来，以及修改功能时不能破坏哪些规则。

## 项目定位

API Balance 是一个自托管的 API 余额与用量监控面板，可通过 Docker、飞牛 Native FPK 或 Android 独立应用运行。用户添加多个 API 中转站后，程序定时查询站点提供的余额、额度或日志接口，并把不同平台的结果统一展示。

API Balance 不承担以下工作：

- 不转发 OpenAI、Claude、Gemini 等模型请求。
- 不出售或充值额度。
- 不绕过站点权限，也不抓取必须登录的网页。
- 不根据累计额度虚构按天、按模型或按请求的明细。

## 运行组成

| 部分 | 位置 | 职责 |
| --- | --- | --- |
| 网页 | `public/` | 响应式界面、表单、总览、文档与更新状态 |
| HTTP 服务 | `server/index.js` | API 路由、定时刷新、阈值判断和静态文件服务 |
| 站点适配 | `server/probe.js`、`server/providers.js` | 发送站点请求并解析余额与用量 |
| 数据存储 | `server/store.js` | 配置合并、凭据加密、余额历史和数据迁移 |
| 通知发送 | `server/notify.js` | Bark、Server酱、PushPlus、Telegram 和 Webhook |
| 飞牛应用 | `fnos/` | 原生 FPK、端口向导、桌面入口、代码更新和失败回滚 |
| Android 应用 | `android/` | 本机查询、Keystore 存储、后台任务和 APK 更新 |
| Scripting 小组件 | `scripting/api-balance-direct/` | iPhone 直连各站，不经过本服务。导入说明见[Scripting 小组件](Scripting小组件.md) |
| 服务端持久化 | `DATA_DIR` | `config.json`、`history.json`、`secret` 和更新状态；Docker 通常为 `/data`，飞牛为应用数据目录 |

网页没有前端构建步骤，Node 服务没有第三方运行时依赖。Docker 使用 Node.js 20，飞牛原生包声明 `nodejs_v22` 系统依赖；Android 使用系统 WebView 和 AndroidX WorkManager。

## 核心数据流

1. 页面打开后读取 `/api/bootstrap` 与 `/api/state`。
2. 页面调用 `/api/refresh`，后端只刷新已启用且设为自动查询的站点；单站点手动刷新可显式指定 `id`。
3. `probe.js` 把平台响应转换为统一字段：余额、币种、已用、总额、请求数和状态。
4. `store.js` 按当前汇率换算美元汇总，并保存余额历史。
5. 页面按站点和时间范围读取 `/api/usage`；没有日志接口时只展示汇总。
6. 后台每分钟独立检查阈值；达到或错过设定时间后，使用最近保存的余额向启用渠道发送当天提醒。

## 余额与用量的边界

余额接口回答“现在还剩多少”，日志接口回答“什么时候、哪个模型、哪次请求用了多少”。这两类接口不能互相替代。

- 自定义计费表单映射余额、已用、总额和套餐名称；自定义用量表单映射平台已提供的周期汇总。
- 按日、模型和 Token 统计必须由用量接口返回，逐条请求列表必须由日志接口返回。
- 当前请求级日志只内置 derouter 适配；SoleAPI `/v1/usage` 是周期汇总，不是逐条日志。
- 平台没有返回的数据必须显示为未知或不支持，不能按 `0` 处理。

配置新站点时，请同时阅读[余额与用量接口配置](余额与用量接口配置.md)和中转站官方文档。

## 安全与持久化

- Docker 版使用 `APP_SECRET` 加密凭据；飞牛版使用应用数据目录中的随机密钥；Android 使用 Keystore 设备密钥。
- `/api/state` 只返回是否已配置和掩码，不返回凭据明文。
- Docker 的 `APP_SECRET`、`data/` 和 `docker-compose.yml` 必须一起备份，更换 `APP_SECRET` 后旧凭据无法解密。
- 飞牛与 Android 使用各自的应用私有数据；原生 FPK、Docker 和 Android 之间不会自动共享数据或加密密钥。
- 飞牛 `v1.16.5` 起把日常更新代码保存在应用数据目录的 `runtime/`，并保留上一版用于启动失败回滚；站点、历史、密钥和许可证不在该目录中。
- 面板没有内置登录，不能直接暴露到公网；应使用反向代理认证、VPN、防火墙或 NAS 权限。
- 自定义计费、用量和 Webhook 地址会由服务端主动访问，只应配置可信目标。
- 配置写盘失败必须向 API 调用方报错，不能返回虚假的保存成功。

## AI 修改规则

让 AI 修改本项目时，应先确认以下约束：

1. 保留现有站点配置和旧版本数据迁移能力。
2. 新凭据必须加密落盘，读取接口不得返回明文。
3. 新平台优先使用页面中的余额或周期用量字段映射；只有分页逐条日志需要新增后端适配。
4. 新推送渠道复用统一阈值与每日去重逻辑，只实现自己的 HTTP 请求格式。
5. 桌面端和移动端必须都能访问新增功能。
6. 修改后至少运行 `npm test`、`node --check public/app.js` 和浏览器响应式检查。
